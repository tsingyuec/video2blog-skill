# 博客写作规范（金字塔写作风格 + 初学者可读）

本规范用于把 `transcripts/<视频ID>.md`（原始文稿：图片 + 合并字幕 + 时间戳）改写成 `blog/blog.md`。

## 0. 第一原则：基于文稿，不凭空发挥

- 内容必须来自原始文稿（字幕 + 幻灯片）；不得编造视频之外的事实。
- 字幕可能由 AI 生成（B 站 AI 字幕 / YouTube 自动字幕），存在生成不准确的情况，要结合上下文纠正，例如：
  - `cs three three nox` → **CS336**
  - `PERCY` → **Percy Liang**；`TO/TAC` → **Tatsu**；`兔20年` → **20 年**
  - `tension`（双关语处）→ **attention（注意力）**；`mob two` → **Mamba-2**
  - 术语、论文名尽量还原正确拼写；拿不准的人名/数字**保持中性表述**（如"来自中国的开源权重模型"），**不要编造**。

原始文稿的窗口文本是字幕逐句拼接，直接照抄会不通顺。写博客前先**逐窗口改写**：

- 可以润色、合并断句、纠正错拼，但**不得丢信息**；无字幕窗口（`> （此区间无字幕）`）保持原样。
- 只改 `> ` 行文本，不动标题、图片名、窗口顺序。
- 用 `scripts/transcript_windows.py dump`（导出 `NNNNN|文本`）+ `scripts/transcript_windows.py apply`（heredoc 写回，**必须写结束分隔符**）做"导出→改写→写回"循环，每批 30–60 个窗口。
- 改写完成后**不要重跑** `build_transcript.py`（会覆盖已修复文本）。

## 1. 金字塔写作风格（把思想组织成“金字塔”）

**四条原则（写完逐条自检）：**

1. **结论先行**：全文/每节先把中心思想（结论）放在最前面，再展开理由。
2. **以上统下**：上一层是下一层的总结概括。例如“水果”概括“苹果、梨、香蕉”。
3. **归类分组**：同一组里的思想必须属于同一逻辑范畴（可被同一个名词概括）。
4. **逻辑递进**：组内按某种逻辑顺序排列。

**序言用 SCQA（背景-冲突-疑问-回答）：**

- 背景（S）：读者已知的事实。
- 冲突（C）：出现的变化/问题。
- 疑问（Q）：冲突自然引出的疑问。
- 回答（A）：你的中心思想（= 全文结论，做到结论先行）。

只写读者已知的信息作为背景；别把新信息塞进序言。

**MECE：** 组间“相互独立、完全穷尽”。快验：任一项挪到另一组也说得通 = 有重叠；沿流程走一遍发现漏项 = 不穷尽。

**一组要点 3–5 个最佳**（人短期记忆 7±2，最好只放 3 个）。超过就分组、提高抽象层。

**组内只有 4 种逻辑顺序：** 时间/步骤、结构/空间（整体→部分）、程度/重要性（最重要→次重要）、演绎（大前提→小前提→结论）。找不到任何一种 = 这组思想无逻辑关系，回去重新分组。

**归纳优先于演绎：** 关键句层次用“归纳”（并列理由，读者易跟）；只有在需要严格证明的下层才用“演绎”。

**标题要传递观点：** 写完整判断句（如“前置归一化更利于大模型训练”），不要只写分类词（如“归一化对比”）。

## 2. 初学者可读

- 目标读者：初学者。
- **术语首次出现必须当场解释并举例**。
- 每个概念讲清三件事：**是什么 → 为什么需要 → 怎么做 / 举个例子**。
- 多用类比与具体例子；抽象处一定落地。

## 3. 文章结构模板

```markdown
# 第N讲：<中文主题>

## 本讲要解决的核心问题（SCQA）
**背景**：…
**冲突**：…
**疑问**：…
**回答（中心思想）**：…          ← 结论先行

## 一、<章节名（观点句）>
### 1.1 <小节名>
正文…（可含列表、公式、伪代码、配图、时间戳）

### 1.2 <小节名>
…

## 二、<章节名>
…（全篇通常 6–10 章；按内容逻辑分组，不要用「## 要点N：…」的平铺风格）

## 小结
- 3–8 条，金字塔式回顾

## 关键术语速查
| 术语 | 一句话解释 |
| --- | --- |
```

## 4. 配图

- 配图挑选最影响成品：去重留下的代表帧 ≠ 有用帧，务必**逐张读图核对**后再入选。
- **优先**含文字 / 图表 / 公式 / 示意图的幻灯片；**剔除**纯产品渲染、Logo、装饰与转场帧。
- 从 `transcripts/img/<视频ID>/` 挑 **8–16 张**，复制到 `blog/assets/`，沿用原文件名（如 `00060.jpg` = 第 60 秒）。
- 引用：`![图注](assets/00060.jpg)`，**图注用一句话说明这张图帮读者理解什么**。

## 5. 时间戳跳转链接

关键知识点处插入：

```markdown
[【跳转到 MM:SS】](https://www.bilibili.com/video/<BV>/?p=<分P>&t=<秒>)
```
其中 `t` 为整数秒，`MM:SS` 由 `t` 换算，两者必须一致。


## 6. 篇幅与覆盖

- **完整覆盖**文稿中的所有重要知识点，不得为省事省略；宁可长，不可粗。
- 典型单讲博客约 8,000–12,000 字（随视频时长与信息量而定）。

## 7. 长文任务的工程建议

- 单次读完 80–130KB 文稿并一次成文，容易因负载过大而中断。
- 推荐：**分段读取、边写边追加**（先写序言 + 前半要点，再读后半并追加），或按讲次拆成多个子任务并行。
